# 项目计划书（草稿）：丹麦登记数据经济学圈的外生冲击

状态：草稿，等你确认后今晚开始跑。这个文件还没有提交到 GitHub。

## 1. 研究问题

当一个研究圈子失去（或得到）一位核心人物时，周围的人产出会怎样变化？

具体到丹麦：作者去世、核心学者离开或加入丹麦、研究中心资助到期、数据访问规则变化，
这些与个人研究质量无关的事件，是否改变了合作者和所在机构的发表数量、发表档次和合作结构。

## 2. 目前手上有什么

- 本站 184 篇论文、343 位作者、合作网络、每篇论文的致谢（资助方、被感谢的人）。
- 873 名目前在丹麦的经济学研究者名单及其领域（来自 OpenAlex）。
- 已核实的去世事件 3 个：Dale Mortensen（2014-01）、George Neumann（2015-10）、Gert Wagner（2024-01）。
- 缺的：每个人完整的逐年发表记录、逐年所在机构、完整的事件清单。

## 4. 事件怎么找、怎么核实

1. **去世**：对全部核心人员查 Wikidata；对 1985 年以前开始发表的资深作者，以及发表记录突然中断
   5 年以上的人，逐个网络搜索讣告。每条记录来源链接；找不到来源的不算。
2. **迁入和迁出丹麦**：从机构–年份面板里找"连续 3 年以上在丹麦，之后连续 3 年以上在国外"（及反向）
   的人，再对其中论文多、丹麦合作者多的人逐个查简历核实年份。
3. **研究中心起止**：CAM、EPRU、CREATES、FRIC、CEBI 等，从丹麦国家研究基金会和各中心网页核实起止年份。
4. **数据访问规则**：从丹麦统计局网页和公开文件核实远程访问、国外研究者访问、收费的变化年份。
   这一项最可能查不全，查不到就如实记录。

"意外"与否无法从数据判断。去世按死因和年龄粗分（在职期间去世算意外）；迁出一律当作可能内生，
只做描述，不当作干净的冲击。

## 5. 分析（阶段 1）

1. **去世事件研究**：处理组是去世者生前的合作者；对照组是同领域、职业年龄相近、事前产出相近、
   但不是合作者的人。画事件前后各 8 年的年发表数、主要期刊篇数、新合作者数。
2. **核心学者迁出／迁入**：同样的设计，处理组是该学者在丹麦的合作者。
3. **机构层面**：中心起止前后，该机构该领域的产出变化，与丹麦其他机构同领域比较。
4. **数据访问规则**：规则变化前后，有国外作者的丹麦数据论文占比的变化。

## 6. 必须先说清楚的局限

- **事件数很少**。目前确认的去世只有 3 个，其中与丹麦关系紧密的 2 个。即使扩大到全部丹麦经济学研究者，
  也可能只有十来个。所以去世部分更接近案例研究，统计功效低，结论只能是"与某种效应一致"，不能是"证明"。
- **迁出不是外生的**。人离开往往正是因为产出好或合作关系变了。
- **OpenAlex 的作者归并有误差**：同名的人可能被合并，一个人可能被拆成几个；机构信息也有错
  （之前已经发现把 Raj Chetty 记成在哥本哈根大学）。
- **两位去世者集中在同一个小群体**（奥胡斯的搜寻匹配方向），所以两个事件不独立。

## 7. 明早交付什么

- 数据文件（作品表、两个面板、事件表）和生成它们的脚本。
- 一份报告：事件清单及来源、每个事件的事件研究图、哪些查不到或失败了。
- 一份核查记录：每个事件是怎么确认的。

全部放在一个新分支上，不合并到 `main`，不上线到网站。涉及去世和个人职业变动，公开之前由你先看。

## 8. 运行上的风险

- **会话可能被回收**：这个云端环境闲置一段时间后会被回收。我会每完成一个阶段就提交并推送到分支，
  这样即使中断，已完成的部分不会丢。
- **OpenAlex 限速**：没有 API 密钥时不能用游标翻页，只能按页码翻，每个查询最多 1 万条。
  按人查询够用；如果你能提供一个免费的 OpenAlex API 密钥，会更快更稳。
- **仓库是公开的**：分支也是公开可见的。如果你不想让未核实的事件表公开，
  我可以只推送脚本和汇总结果，把逐人数据留在会话里（但会话回收后就没了）。
- **体量**：作品表可能有几十 MB，我会压缩后再提交，或只提交面板。

## 9. 需要你决定的

1. **主问题**：以去世事件为主（干净但样本极小），还是以核心学者流动为主（样本大但不外生），还是两个都做？
2. **人群范围**：只做本站 343 位作者，还是扩大到丹麦全部约 870 名经济学研究者？
3. **数据放哪**：逐人数据可以推到公开仓库的分支，还是只推脚本和汇总结果？
4. **结果指标**：最看重哪个——论文总数、Top 5 和主要期刊篇数、引用数，还是合作结构？
